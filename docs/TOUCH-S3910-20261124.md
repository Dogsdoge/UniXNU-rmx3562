# S3910 Touch Driver for MT6895 — 移植分析（2026-11-24）

> 剩余工作量主体之一 = 触控驱动。找到现成参考，难度从"从零写"降为"移植"。

## 发现：现成 S3910 驱动

来源：`v1-727/Sm8475SynapticsTouch`（oplus 设备，2026-11-05）
- `SynaTcm.c` (9KB) + `SynaTcm.h` (4KB) — 已拷到 `reference/s3910/`
- 另一个：`jiganomegsdfdf/OnePlus_aston_Touch_WOA_S3910`（OnePlus 12R）

## 为什么这个参考很理想

1. **纯 C、无 Linux 内核依赖**：用户态风格代码，只用 I2C 命令 + 内存操作
2. **S3910 从自己 flash 启动**：无需固件下载（syna_setup 注释明确），简化初始化
3. **协议清晰**：IDENTIFY → GET_APP_INFO → 读 report config → ENABLE_REPORT → parse touch
4. **oplus 设备**：跟 realme RMX3562 同厂商，硬件行为接近

## 移植到 XNU 的工作量

- I2C 传输：`syna_command()` 的 I2C read/write → 换成 XNU 的 I2C nub（`IOI2CDevice` / 直接 I2C controller）
- 中断：S3910 IRQ（我们真机 gpio135 附近，需从 DT 确认）→ XNU 的 IOInterruptEventSource
- 输入注入：parse 出的触摸坐标 → XNU 的 IOHIDSystem（参考 SLNeko 的 redwood_input.c / UniXNU 的 HID 框架）
- 设备树：从 ADT 的 i2c 节点读 S3910 地址 + IRQ

预估：1-2 周（有现成协议代码，主要是 XNU IOKit 胶水）

## 驱动参考修正

找到的 `SynaTcm.c`（v1-727）是 I2C 风格 → 协议层（IDENTIFY/GET_APP_INFO/
ENABLE_REPORT/parse）可参考，但传输层要改成 SPI。
另一个 `Project-Aloha/atoll-synaptics-tcm` 是 Windows vhidmini 驱动，不适用 XNU。
⇒ XNU 驱动需要：SPI nub 传输 + synaptics_tcm 协议 + IOHID 注入。工作量 1-2 周。
